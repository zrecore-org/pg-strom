# Tests on the vulkan-gpu branch (moved out of CLAUDE.md)


CPU fallback (A14): `sh test/gpuserv/locked_test.sh "$PWD" fallback_dev.sh` runs `test/gpuserv/fallback_tests.inc` (fault injection through `pg_strom.gpuserv_fault`, compared with `pg_strom.enabled=off`). GPU-Cache: `sh test/gpuserv/locked_test.sh "$PWD" gpucache_dev.sh` runs `test/gpuserv/gpucache_tests.inc` alone (the full `scan_test.sh` sources it); `make -C src/gpuserv gcache_check && src/gpuserv/gcache_check` checks the cache store without a GPU.

`make -C src/gpuserv feat_check && src/gpuserv/feat_check` checks the kernel tier classification of every opcode without a GPU (also run by `spec_compile_check.sh`); `sh test/gpuserv/locked_test.sh "$PWD" tier_latency.sh` prints the first-query latency and the interpreter pipelines (SPIR-V size, creation time) per tier, next to the same queries with `PGSTROM_GPUSERV_TIERS=full`.

```
GPUSERV_BIN=src/gpuserv/pgstrom-gpuserv sh test/gpuserv/service_test.sh     # service lifecycle (throwaway cluster)
GPUSERV_BIN=<installed pgstrom-gpuserv> sh test/gpuserv/scan_test.sh        # GPU vs CPU result comparison of GpuScan
sh test/gpuserv/locked_test.sh <tree> jsonb_test.sh                           # only the jsonb section of scan_test.sh (jsonb_tests.inc)
make -C test/port && test/port/port_test                                    # portability layer
sh test/gpuserv/f64soft_check.sh [N [device|-1]]                              # software binary64 (kernels_vm/f64_soft.inc) vs the hardware double, on the host and the device (no lock, no cluster)
sh test/gpuserv/spec_compile_check.sh                                       # generator: every kernel kind's generated source compiles with slangc (no GPU, no lock)
sh test/gpuserv/locked_test.sh "$PWD" spec_dev.sh                           # kernel specialization tests on a small data set (the section scan_test.sh sources as spec_tests.inc)
sh test/gpuserv/locked_test.sh "$PWD" coverage_test.sh                      # A14 coverage assertion: ~600 join / GROUP BY shapes must plan as GpuJoin / GpuPreAgg unless listed in coverage_cpu_allowed.txt (the list may only shrink); GPU rows = CPU rows; prints the gap table (COVERAGE_ONLY=<regex>, COVERAGE_ROWS=0 for EXPLAIN only)
sh test/gpuserv/locked_test.sh "$PWD" perf_bench.sh                         # benchmark: 16.8M rows, GPU vs 8-worker PostgreSQL, kernel ms per task (SPECS="off default" compares variants)
```

Tooling for the test runs (details in the `vulkan-verify` and `gpu-hang-triage` skills under `.claude/skills/`): `sh test/gpuserv/affected.sh` maps the changed files to the dev scripts to run (`RUN=1` runs them); `verify_all.sh` writes `<log>.times` (seconds per group of checks and the slowest checks, `timeline.pl`) next to each stage log, stops the cluster of a stage that timed out, and runs every stage with `PGSTROM_GPUSERV_SPECIALIZE=check`; every `psql` call of the test scripts has a limit (`QUERY_TIMEOUT`, default 900 s, `qtimeout.sh`: after one timeout the rest of that test fails at once); `SHARDS=<n> ... scan_shards.sh` splits `scan_test.sh` into parallel parts (not on an Apple GPU: macOS killed a Metal command buffer, "Impacting Interactivity", with 3 services). Resource use: `locked_test.sh` runs the build (`TEST_JOBS`, default 3) and every test at `nice -n 10` (`TEST_PRIORITY=nice|background|full`; `background` = `taskpolicy -b`, which also throttles disk I/O and made a dev script 5x slower; `TEST_FULL_SPEED=1` = full), and the throwaway clusters get `test/gpuserv/pgconf_test.sh` (no fsync or full-page writes, rare checkpoints, at most 4 parallel workers, autovacuum off; the installcheck only the I/O part). After the install, `locked_test.sh` runs `prewarm_kernels.sh`: the interpreter kernels whose SPIR-V changed since the last run (checksums in `<cache dir>/prewarm.sums`, a fixed set of the common variants, `PREWARM=off|all`) are compiled once, one after the other, by `pgstrom-gpuserv --prewarm`, and the service's persisted `VkPipelineCache` (`pipeline-*.bin` in the kernel cache dir, `PGSTROM_GPUSERV_PIPELINE_CACHE=off`) hands the result to every later service start (full join pipeline 5 s -> 10 ms). A full `verify_all.sh` (installcheck + scan) takes about 28 minutes warm at these limits; the first run after a change of `kernels_vm/` is slower while the driver compiles the kernels.

The differential fuzzer (`test/gpuserv/fuzz.py`, standard library Python; random expression trees, aggregates, GROUP BY and joins over edge-value tables, each query run on the GPU path and with `pg_strom.enabled=off`; comparison rule and generator in the script header) runs through the same lock: `FUZZ_SEED=1 FUZZ_COUNT=2000 sh test/gpuserv/locked_test.sh "$PWD" fuzz_test.sh` (do not run it through `verify_all.sh`'s check mode: which row reports a kernel error first is a race, and the VM-versus-specialized comparison then fails with "first error ... differs"; or `FUZZ_TIME=<seconds>`; `FUZZ_ARGS="--only N"` reproduces query N of a seed, `DBG_SQL=<file>` runs ad-hoc SQL against its tables). Failing queries are minimized and appended to `test/gpuserv/fuzz_corpus.txt`, which the next run replays first; bugs it found have regression tests in `test/gpuserv/fuzz_regress.inc` (part of `scan_test.sh`).

`sh test/gpuserv/locked_test.sh <tree> [scan_test.sh|service_test.sh]` installs a checkout and runs a test while holding a global lock (the installed `$libdir/pg_strom` is shared, so parallel worktrees must queue). The wrapper also picks the cluster directory (when `ROOT` is not set) and removes it after a passing test: `perf_bench.sh` / `arrow_bench.sh` run on the local drive (`PGSTROM_BENCH_ROOT`, default `/tmp`) because disk speed matters there, everything else on the external volume (`PGSTROM_TEST_DATA`, default `test-data/` of the main checkout) because the local drive is nearly full. Runs queue in a FIFO order (ticket directories `/tmp/pgstrom_test.lock.queue/<n>`; a ticket whose process is gone is dropped; `PGSTROM_TEST_LOCK` moves the lock, `LOCKED_TEST_LOCK_ONLY=<s>` tests the queue itself; a process counts as alive only with the same pid and start time, so a recycled pid cannot keep a dead run's ticket or lock; the holder touches `$LOCK/beat` every minute and waiters print every 10 minutes how long the lock has been held, whether the heartbeat is fresh and whether the holder's cluster directory changed in the last 30 minutes, with a WARNING after 60 minutes or 3 minutes without a heartbeat); the wrapper notes when the tree is behind `vulkan-gpu` (merge first: checkouts sharing kernel sources share the compiled kernels), and `prewarm_kernels.sh` warms only what the script needs (`PREWARM_FOR`, set from the script name: scripts without geometry skip the full-tier kernels, about 5 minutes each when cold; `PREWARM_SET=all|nongeom`, `PREWARM_LIST_ONLY=1` to see the list). `KEEP=1`, `KEEP_RUNNING=1`, `HOLD=1` or `REUSE=1` keep the cluster, a failed test keeps it for diagnosis, and a `ROOT` you set is never removed (so a kept regression dataset needs `ROOT=...`). Both shell tests build a throwaway cluster and need the module and service installed (`make install` above). `ALLOW_CPU=on` runs them on lavapipe (Linux). `PGSTROM_GPUSERV_TRACE=1` in the postmaster's environment makes the service log each session's xpucode and per-task timings (`PGSTROM_GPUSERV_SPEC_LOG=1`: what the specializer does; `scan_test.sh` runs with `PGSTROM_GPUSERV_SPECIALIZE=check`: every dispatch runs the VM kernel and the specialized one and compares); `PGSTROM_GPUSERV_NO_MAP=1` disables the zero-copy file mapping.

The upstream regression suite (PGXS `pg_regress` from `test/`, database `contrib_regression_pg_strom`, dataset revision in `test/Makefile`) has a Vulkan subset. `test/vulkan_schedule` (23 tests) must pass, `test/pending_schedule` holds what cannot yet (`conv_text_inet`; every other test file is listed there with a reason), and `test/vulkan_known_failures.txt` explains each difference from upstream's expected output. Run it against a throwaway cluster that keeps its 2 GB dataset between runs (about 3 minutes, plus about 20 seconds for the first dataset load; needs the module installed, so under the shared test lock):

```
sh test/gpuserv/locked_test.sh "$PWD" test/vulkan_installcheck.sh                        # vulkan_schedule: expect "All 23 tests passed"
TARGET=pending-installcheck sh test/gpuserv/locked_test.sh "$PWD" test/vulkan_installcheck.sh   # pending_schedule (fails by design)
sh test/gpuserv/locked_test.sh "$PWD" test/vulkan_regen_expected.sh                      # regenerate the PG17 alternate expected files
make -C test PG_CONFIG=... vulkan-installcheck                                           # the same against a running server (PGHOST/PGPORT)
```

`pg_regress` accepts `<test>.out` and `<test>_0..9.out`: `<test>_9.out` is this branch's (plan text differs because float8, numeric, text, jsonb and joins are not on the GPU yet); `vulkan_regen_expected.sh` writes it only after the output without its `EXPLAIN` blocks equals the same test run with `pg_strom.enabled` forced off (`make vulkan-oracle`), and reports a `ROW DIFF` otherwise. Only PostgreSQL 17 has `_9` files: on a host with 15, 16, 18 or 19 run the regen script with `PGBIN` pointing at that server (until then `vulkan-installcheck` means something on 17 only). The order of parallel-append children in `partition` can flip with the random ANALYZE sample (it did once on the earlier tree): if so, keep the flipped output as `partition_8.out` too. `arrow-tools` (`pg2arrow`, `arrow2csv`) now build on macOS and the Arrow tests need them. Run a single test with `make -C test ... installcheck REGRESS=--schedule=<file>` (a schedule file with one `test:` line) or invoke `pg_regress` directly with the options of `test/Makefile` (`--use-existing`).
