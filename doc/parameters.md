# Configuration parameters (Vulkan build)

Every parameter below is read from the `DefineCustom*Variable()` calls in `src/*.c` (the list is
regenerated by `grep -n DefineCustom src/*.c`) and compared with `master` (the CUDA product). The
"Since CUDA" column says what changed:

- **same**: registered by `master` with the same default and meaning;
- **changed**: same name, different default or description;
- **new**: does not exist on `master`;
- **no effect**: still registered (so a configuration that sets it keeps working) but nothing on this branch reads it, or the feature it controls does not exist.

Names ending in a context: `postmaster` parameters are set in `postgresql.conf` and need a restart,
`user` can be changed per session, `superuser` only by superusers.

**Registration depends on the GPU.** The parameters in sections 2 and 4 to 6 are registered only
when the start-up probe found a usable device (`pgstrom_init_gpu_device()` in `src/main.c` gates
them). Without a usable device, `SHOW pg_strom.enable_gpuscan` fails with "unrecognized
configuration parameter" (a `SET` of an unknown `pg_strom.*` name is accepted as a placeholder and
does nothing). The always-present ones are in sections 1, 3 and 7.

## 1. General (always registered)

| Parameter | Type, default, context | Meaning | Since CUDA |
|---|---|---|---|
| `pg_strom.enabled` | bool, `on`, user | Master switch of PG-Strom in the planner. `off` gives PostgreSQL's own plans (the test suites use it to get the CPU's answer). | same |
| `pg_strom.cpu_fallback` | enum (`off`/`false`/`no`/`0`, `on`/`true`/`yes`/`1`, `notice`), `off`, user | Elevel of the "CPU fallback" message. In the CUDA product `on` let a task that needed a re-run fall back to the CPU. **Here the GPU service never returns fallback chunks** (no `KDS_FORMAT_FALLBACK` in `src/gpuserv/`), so a kernel error such as division by zero still fails the query. A setting other than `off` only changes planning: GPU-Sort and the pinned inner buffer of GpuJoin are not planned. Rows the kernel cannot evaluate (compressed or out-of-line TOAST text) are re-evaluated by the backend regardless of this parameter (plan A6). | same name; behavior reduced |
| `pg_strom.explain_developer_mode` | bool, `off`, user | Adds internal detail to `EXPLAIN` (xpucode dumps with `VERBOSE`, Parquet cache lines, ...). | same |
| `pg_strom.enable_gpucache` | bool, `on`, user | Use a table's GPU-Cache (see `doc/features.md`) for scans, aggregates and joins. Off: the table is read (the trigger still logs). | same |
| `pg_strom.gpucache_max_relation_entries` | int, 1024 (min 1024), postmaster | Number of tables that can have a GPU-Cache at once (shared memory entries). | same |
| `pg_strom.gpucache_log_buffer_size`, `pg_strom.gpucache_sync_interval`, `pg_strom.gpucache_sync_threshold` | postmaster | Accepted for compatibility with the CUDA product. They have no effect: the redo log is sent to the GPU service synchronously (see `doc/features.md`). | `pg_strom.gpucache_*` |
| `pg_strom.regression_test_mode` | bool, `off`, user (hidden from `SHOW ALL`) | Hides platform-specific `EXPLAIN` output (for example `Scan-Engine`) so expected files stay stable. | same |
| `pg_strom.enable_brin` | bool, `on`, user | Use BRIN indexes to skip block ranges for a GPU scan. | same (the BRIN code is unchanged; not covered by the Vulkan tests) |

## 2. GPU service and devices

| Parameter | Type, default, context | Meaning | Since CUDA |
|---|---|---|---|
| `pg_strom.gpuserv_path` | string, `<pkglibdir>/pgstrom-gpuserv`, postmaster | Path of the GPU service executable. If it is not executable the log says "GPU service ... is not available; running without GPU". Registered even without a device. | **new** |
| `pg_strom.gpu_visible_devices` | string, empty (all), postmaster | Comma-separated Vulkan device indexes (`dev_id` in `pgstrom.gpu_devcaps()`) PG-Strom may use. The first usable allowed device is selected; only one device is used. Registered even without a device. | **new**; replaces `pg_strom.cuda_visible_devices` |
| `pg_strom.gpu_allow_cpu_device` | bool, `off`, postmaster | Allow a Vulkan device that runs on the CPU (lavapipe). Meant for testing. Without it such a device gets tier `none` ("CPU device (use --allow-cpu)"). Registered even without a device. | **new** |
| `pg_strom.gpuserv_probe_timeout` | int, 60000 ms (1000 to 600000), postmaster | Time limit of the start-up probe; the probe is killed after it and PG-Strom runs without GPU. Registered even without a device. | **new** |
| `pg_strom.max_async_tasks` | int, 16 (1 to 256), superuser | Limit of concurrent GPU tasks of one backend: tasks in flight and results waiting to be consumed (`src/executor.c`). | changed (description only; now read directly) |
| `pg_strom.debug_level` | int, 0 (0 to 2), user | Verbosity of PG-Strom's own debug messages (`__Info` at 1, `__Debug` at 2). | **new** name; takes the place of `pg_strom.extra_ereport_level` |

| `arrow_fdw.stats_hint_enabled` | bool, `on`, user | Use the min/max statistics of record batches to skip them. | same |

## 4. Planner switches (registered only with a usable device)

| Parameter | Type, default, context | Meaning | Since CUDA |
|---|---|---|---|
| `pg_strom.enable_gpuscan` | bool, `on`, user | Allow GpuScan. | same |
| `pg_strom.enable_gpupreagg` | bool, `on`, user | Allow GpuPreAgg. | same |
| `pg_strom.gpupreagg_max_groups` | int, 16 (1 to INT_MAX), user | Largest *estimated* number of groups for which GROUP BY is planned on the GPU; above it the aggregation stays on PostgreSQL. 16 is where the GPU currently wins (about 1.3x at 7 groups, slower at 100, plan A3); raise it only for experiments. | **new** |
| `pg_strom.enable_gpujoin` | bool, `on`, user | Allow GpuJoin. | same |
| `pg_strom.enable_gpuhashjoin` | bool, `on`, user | Allow hash joins in GpuJoin (the only kind implemented). | same |
| `pg_strom.enable_partitionwise_gpupreagg`, `pg_strom.enable_partitionwise_gpujoin` | bool, `on`, user | Partition-wise variants. Kept from the CUDA product; partitioned-table behavior has no dedicated Vulkan test (the plan says partitioned Arrow tables are untested). | same |
| `pg_strom.enable_gpusort` | bool, **`off`**, user | GPU-Sort of the groups of a GpuPreAgg (`GROUP BY ... ORDER BY`, `LIMIT`, window-rank filter; plan item A7). Only built for non-parallel plans with `pg_strom.cpu_fallback = off`. Sorting GpuScan/GpuJoin results is not implemented. The default was `on` in the CUDA product. Environment of the service: `PGSTROM_GPUSERV_SORT=cpu|gpu` forces an engine, `PGSTROM_GPUSERV_SORT_MIN` is the number of groups from which the device sorts (default 16384). | **changed** (default) |
| `pg_strom.enable_gpugistindex` | bool, `off`, internal (cannot be set) | GiST-index join. Not implemented here. | same (but read-only) |
| `pg_strom.enable_numeric_aggfuncs` | bool, `on`, user (hidden) | Aggregates on `numeric`. They stay on the CPU in this branch whatever the value (no device numeric yet). | same; no effect |
| `pg_strom.debug_xpujoinpath` | bool, `off`, user | Debug output about join paths the planner considered. | same |

## 5. Planner costs (registered only with a usable device)

| Parameter | Type, default, context | Meaning | Since CUDA |
|---|---|---|---|
| `pg_strom.gpu_setup_cost` | real, `100 * seq_page_cost` = 100, user | Cost of setting up a GPU run. Tests set it to 0 to force a GPU plan on small tables. | same |
| `pg_strom.gpu_tuple_cost` | real, `cpu_tuple_cost` = 0.01, user | Cost of moving one tuple between the GPU service and the backend. | same |
| `pg_strom.gpu_operator_cost` | real, `cpu_operator_cost / 16` = 0.00015625, user | Cost of one operator on the GPU. | same |
| `pg_strom.gpu_direct_seq_page_cost` | real, `seq_page_cost / 4` = 0.25, user | Cost of a sequential page read by the GPU service. The name is a leftover of "GPU-Direct SQL"; there is no GPU-Direct here. | **changed** (description only) |

The cost model was not re-tuned for Vulkan: the plan notes that joins win when they reduce rows
or feed an aggregate, and that the planner "has not been tuned for that" (plan A4).

## 6. GpuJoin pinned inner buffer (registered only with a usable device)

| Parameter | Type, default, context | Meaning | Since CUDA |
|---|---|---|---|
| `pg_strom.pinned_inner_buffer_threshold` | int, 0 = disabled (MB), superuser | Inner size above which the join's inner buffer would stay in GPU memory for later nodes. **Leave at 0:** the Vulkan service does not support pinned buffers and answers such a task with an error (plan A4). | same name; feature gone |
| `pg_strom.pinned_inner_buffer_partition_size` | int, computed from the device memory (min 1024 MB), superuser (hidden) | Unit of a partitioned pinned inner buffer. | same name; feature gone |

## 7. Removed (CUDA product only)

These no longer exist; setting them has no effect (see [install.md](install.md)):

| Removed | Replacement or reason |
|---|---|
| `pg_strom.cuda_visible_devices` | `pg_strom.gpu_visible_devices` (device indexes) |
| `pg_strom.cuda_toolkit_basedir`, `pg_strom.cuda_stack_limit` | no CUDA |
| `pg_strom.gpudirect_enabled`, `pg_strom.gpudirect_threshold`, `pg_strom.gpudirect_driver` | GPUDirect Storage is dropped; the CPU reads storage |
| `pg_strom.extra_ereport_level` | `pg_strom.debug_level` |
| `pg_strom.gpu_mempool_max_ratio`, `_min_ratio`, `_release_delay`, `_segment_sz` | the CUDA memory pool is gone (Vulkan buffers are allocated explicitly) |
| `pg_strom.gpu_selection_policy`, `pg_strom.manual_optimal_gpus` | needed `heterodb-extra` for GPU-to-NVMe distance; one device is used |
| `pg_strom.enable_select_into_direct` | SELECT INTO direct mode is removed (the service does not write tables) |
| `pg_strom.parquet_cache_*` (path, size, unitsz, eviction settings, max async write, target usage) | the GPU-side Parquet cache is gone (stub) |

## Environment variables of the GPU service

These are read by `pgstrom-gpuserv`, which inherits the environment of the postmaster; set them
where PostgreSQL is started (for example in the systemd unit) and restart.

| Variable | Effect |
|---|---|
| `PGSTROM_GPUSERV_TRACE=1` | The service logs each session's xpucode and per-task timings to its stderr (the PostgreSQL log). Any value other than empty or `0` enables it. |
| `PGSTROM_GPUSERV_NO_MAP=1` | Disable the zero-copy file mapping: heap pages and Arrow column ranges are read with `pread` instead of being `mmap`ed and imported into Vulkan. Useful to tell a mapping problem from a kernel problem. |
| `PGSTROM_GPUSERV_TIMEOUT_MS=<n>` | Time the service waits for one GPU dispatch before it declares the device lost (default 10000 ms; 300000 ms when the device is a CPU Vulkan device, which compiles each kernel at its first dispatch). |

## Server settings that matter

- `shared_preload_libraries = 'pg_strom'` is required (the module refuses to load otherwise).
- `max_worker_processes`: the launcher takes one slot; parallel workers of a GPU plan each open
  their own session on the service (the service serves at most 64 connections at once, `WIRE_MAX_CLIENTS`).
- The service runs inside PostgreSQL's service unit (systemd) or process tree, so the limits
  and environment of the postmaster apply to it.
